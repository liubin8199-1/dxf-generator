# P0-1 修法②③ 实证：before/after 驳回（不合并）

> 结论：**修法②（火灾报警图关键词扩到 17）与 修法③（火灾报警图图层信号）在 external n=26 上
> 实测会『复活』火灾报警图误判簇（0→5 张），属于用户亲自提示的 ❌误伤，故驳回。**
> 火灾报警图簇已由 **v1.17.13 的窄①（文本级图例过滤 + 图名级关键词匹配）** 单独修好，
> 且已通过 `verify_fire_alarm_fix.py` 验收（火灾报警误判 0 / 严格正确 4 / 认错 17 ≤ 19）。

## 一、为什么测 ②③（背景）

用户（e）在 v1.17.13 之后又给了三件套：
- 修法①（用户版）：**图层名**过滤图例层（`LEGEND_LAYER_KEYWORDS` 含 `标注/说明/标题/图框/材料表/门窗表/轴号/dim`…）
- 修法②：火灾报警图关键词 `("火灾报警","火警")` → 17 个（`消防报警/报警平面/感烟/温感/烟感/手报/声光/总线/探测器/输入模块/输出模块/消防广播/消防电话/消防控制室/火灾探测器/报警主机/消防联动`）
- 修法③：火灾报警图图层信号 `("E-FIRE","E-ALARM","FIRE","ALARM","消防","报警","火灾")`

注意：v1.17.13 已用了**另一套更窄的①**（只删含「图例」二字的文字 + 图名级关键词匹配，
防止 `火警`⊂`火警警铃`、`电气`⊂`机电图例` 子串误中）。用户版①与 v1.17.13 的①机制不同。

---

| 05 2F | 948 | 165 | 17% |
| 01 材料表 | 352 | 57 | 16% |
| …（其余略） | | | 1%–17% |

⚠️ 真实图层 `L标注` / `A建筑标注` / `0-图框、标题、说明` 都含这些宽关键词，

## 四、根因

当前识图匹配是**子串计数**（命中关键词次数 → 加权），没有「图名级」约束。
- ② 的 `探测器/总线/手报/声光` 是**设备名**，不是图名后缀，会被平面/暖通图里的设备标注子串误中。
- ③ 的 `消防/报警/火灾` 是**图层名子串**，会命中一切含这些字的图层（消防系统图、含报警的平面图…）。
- 两者在 26 张里**没有一张真正的火灾报警图可增益**（全是误判），所以纯亏不赚。

---

## 五、结论与建议

1. **保留 v1.17.13 窄①**（已验收达标），**不合并 ②③**。
2. 若日后出现**真正的火灾报警图样本**，再用更稳的机制重测：
   - ② 限「图名级」token（仿 `_type_keywords_in_text` 的后缀约束），不要裸设备名；
   - ③ 用**具体图层前缀**（如 `E-FIRE-*`）而非 `消防/报警/火灾` 子串；
   - 任何改动都必须重跑 `eval.py --external-only` 给 before/after，且 external ≥30 前不调阈值。
3. 回归门禁：`benchmarks/verify_fire_alarm_fix.py`（火灾报警误判≤2 / 严格正确≥3 / 认错≤19），
   达标才允许提交涉及识图规则的改动。
